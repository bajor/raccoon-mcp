# Visual-first explanations

The user found the article too text-heavy and approved enforced visual-first
generation on 2026-10-22. This replaces the presentation priority of
[continuous articles](/prd/0002-continuous-article.md), not their evidence safety.

1. Make diagrams and exact Git excerpts the primary explanation. Include actual
   callers, types and surrounding branches, not only changed lines.
2. Use concise, source-cited captions for non-obvious behavior and constraints.
3. Keep one ordered English artifact with functional chapters, complete change
   ownership, selected history and printable portrait/landscape graphics.
4. Enforce the [publication budgets](/bdr/0009-visual-first-authoring.md) and expose
   [numbered surrounding code](/bdr/0008-code-context.md) to the author.
5. Preserve the version-2 layout, privacy, frozen Git evidence and atomic publication.
   No reader migration, new model call or alternative publishing path is required.

Acceptance: authoring and package tests pass, one requested PR is regenerated
with the revised skill, and the user evaluates its clarity. Physical iPad reading
remains a separate user acceptance gate, not a claim made by server tests.
